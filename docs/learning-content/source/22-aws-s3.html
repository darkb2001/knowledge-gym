S3 cơ bản & storage classes

AWS1 S3 là gì? Bucket, object, key và consistency model

What

Amazon S3 là object storage: dữ liệu lưu thành object trong bucket. Object gồm data + metadata + key (đường dẫn đầy đủ, tối đa 1024 byte UTF-8). Bucket có tên unique toàn cầu, gắn một region, dài 3–63 ký tự. S3 không có thư mục thật — prefix trong key tạo thư mục ảo (img/2026/logo.png). Metadata có thể là system-defined (Content-Type, ETag) hoặc user-defined (tối đa 2 KB mỗi PUT).

How

Từ 12/2020 S3 cung cấp strong read-after-write consistency ở mọi region: sau PUT object mới, ghi đè hoặc DELETE, lần đọc kế tiếp thấy ngay kết quả mới. Thao tác LIST cũng strongly consistent. Mô hình eventual consistency cho overwrite + list là kiến thức cũ — vẫn là bẫy của đề thi cũ.

ClientSDK / CLI / console
→PUT / GET / DELETE
Bucketregion-scoped, tên unique
→key + version id
Objectdata + metadata
# Tạo bucket (tên phải unique toàn cầu) rồi upload object
aws s3 mb s3://my-app-assets --region ap-southeast-1
aws s3 cp ./logo.png s3://my-app-assets/img/logo.png
aws s3api head-object --bucket my-app-assets --key img/logo.png

# Liệt kê theo prefix (thư mục ảo) và xem kích thước
aws s3api list-objects-v2 --bucket my-app-assets --prefix img/ \
  --query 'Contents[].{Key:Key,Size:Size}'

Bẫy thi / Pitfall

5 TB là giới hạn mỗi object, không phải mỗi bucket. Object > 5 GB bắt buộc upload bằng multipart, không thể PUT một phát. Bucket không lồng nhau, và tên bucket dùng chung namespace giữa mọi account nên có thể bị trùng tên.

AWS2 Chọn storage class nào? So sánh Standard tới Glacier Deep Archive

What

S3 có nhiều storage class đánh đổi giữa chi phí lưu trữ, thời gian lấy dữ liệu và availability. Tất cả class đều có durability 99.999999999% (11 số 9) — khác nhau ở availability, thời gian retrieval và minimum storage duration (thời gian lưu tối thiểu bị tính phí).

How

Chọn class theo tần suất truy cập. Khi chưa biết access pattern, dùng Intelligent-Tiering để S3 tự chuyển tier theo ngày không truy cập. Với dữ liệu archive, đi theo mô hình thác nước: Standard → Standard-IA → Glacier Instant Retrieval → Glacier Flexible Retrieval → Glacier Deep Archive.

→180 ngày

# Đổi class object đã có (tạo bản copy mới, giữ nguyên nội dung)

Bảo mật, mã hoá & chia sẻ

AWS3 Block Public Access vs bucket policy vs IAM vs ACL — chọn cơ chế nào?

What

S3 có bốn lớp kiểm soát truy cập hay bị nhầm: Block Public Access (BPA) là công tắc chặn public, bucket policy và IAM policy là policy JSON, còn ACL là cơ chế cũ cấp quyền theo object/bucket. Từ 2023 bucket mới mặc định bật Block Public Access và tắt ACL (bucket owner enforced).

How

Quyết định truy cập là tổ hợp: IAM policy trên principal cộng bucket policy trên resource; request bị từ chối nếu bất kỳ Deny nào khớp hoặc không có Allow nào. BPA là lớp override nằm trên cùng: khi bật, mọi truy cập public qua bucket policy/ACL đều bị chặn bất kể policy nói gì.

Đề hay hỏi \"bucket vẫn public dù ACL private\" — luôn kiểm tra cả bucket policy lẫn BPA. Deny tường minh luôn thắng Allow. Với bucket cross-account chưa tắt ACL, object do account khác ghi lên thuộc sở hữu account đó — bật bucket owner enforced để chủ bucket nắm toàn quyền.

AWS4 Mã hoá S3: SSE-S3 vs SSE-KMS vs SSE-C vs DSSE-KMS

What

Mọi object S3 được mã hoá at-rest (mặc định SSE-S3 từ 05/01/2023). Bốn lựa chọn server-side encryption: SSE-S3 (S3 quản lý key), SSE-KMS (AWS KMS quản lý key, có audit + control), SSE-C (khách tự giữ key), DSSE-KMS (hai lớp mã hoá bằng KMS key).

How

Đặt default encryption cho bucket (chỉ SSE-S3, SSE-KMS hoặc DSSE-KMS — SSE-C không làm default được). Với SSE-KMS, mỗi GET/PUT gọi KMS nên tốn quota và có thể bị throttle; bật S3 Bucket Keys giảm tới 99% request tới KMS. Với SSE-C, mỗi request phải gửi kèm key qua header (bắt buộc HTTPS) — S3 không lưu key.

SSE-S3AES-256, key do S3 quản
SSE-KMSaudit + key policy
SSE-Ckhách giữ key
DSSE-KMS2 lớp, compliance
# SSE-S3 (mặc định) — không cần quản lý key
aws s3 cp ./report.pdf s3://my-app-assets/reports/ --sse AES256

# SSE-KMS với customer managed key (kèm quyền kms:GenerateDataKey / kms:Decrypt)
aws s3 cp ./report.pdf s3://my-app-assets/reports/ \
  --sse aws:kms --sse-kms-key-id alias/app-key

# SSE-C: gửi key trên từng request, S3 không lưu key
aws s3api put-object --bucket my-app-assets --key secret.bin --body secret.bin \
  --sse-customer-algorithm AES256 --sse-customer-key fileb://key.bin
KiểuKey do ai quảnAi đọc đượcGhi chú

SSE-KMSKMSChỉ principal được key policy cho phépTốn KMS quota; bật Bucket Keys để giảm phí
SSE-CKháchAi có key (gửi mỗi request)Không làm default; bắt buộc HTTPS

Bẫy thi / Pitfall

SSE-KMS cần quyền kms:Decrypt/kms:GenerateDataKey; bucket policy chỉ có s3:* là không đủ. KMS quota theo region có thể throttle trước cả S3 — bucket key xử lý việc này. Mã hoá at-rest không thay cho TLS in-transit: dùng điều kiện aws:SecureTransport để ép HTTPS.

AWS5 Presigned URL: chia sẻ object riêng tư không cần public bucket

What

Presigned URL là URL đã ký (SigV4) cấp quyền tạm thời cho một thao tác trên một object, dùng chính credential của người tạo. Ai có URL thì thực hiện được đúng thao tác đó mà không cần AWS credential — bucket vẫn private.

How

URL mang quyền của principal tạo nó: GET để tải xuống, PUT để client upload trực tiếp lên S3 (bỏ qua app server). URL hết hạn thì vô hiệu; hết hạn tối đa 7 ngày (604.800 giây) với credential IAM dài hạn, còn với credential tạm thời (STS) thì không vượt quá vòng đời của token.

Versioning, lifecycle & hiệu năng

AWS6 Versioning, lifecycle, MFA Delete và Object Lock

What

S3 Lifecycle là bộ quy tắc tự động chuyển object sang storage class rẻ hơn (transition) và xoá object hết hạn (expiration). Khi bật versioning, mỗi lần ghi đè/xoá tạo version mới; xoá thường chỉ thêm delete marker. Object Lock là cơ chế WORM chống xoá/ghi đè.

How

Rule gồm Filter (prefix/tag), Transitions, Expiration, NoncurrentVersionExpiration và AbortIncompleteMultipartUpload. Mỗi class có minimum storage duration: Standard-IA/One Zone-IA 30 ngày, Glacier IR/Flexible 90 ngày, Deep Archive 180 ngày — chuyển sớm vẫn bị tính đủ thời gian tối thiểu. MFA Delete đòi MFA để xoá vĩnh viễn một version hoặc đổi trạng thái versioning (chỉ root bật). Object Lock phải bật lúc tạo bucket, không tắt được; có mode Governance (cần s3:BypassGovernanceRetention để vượt) và Compliance (không ai xoá được, kể cả root).

AWS7 Upload/download lớn bị chậm, throttle 503: multipart, prefix và Transfer Acceleration

What

Một ứng dụng upload file lớn (vài GB) bị chậm và thỉnh thoảng nhận 503 SlowDown. Một PUT đơn tối đa 5 GB; để nhanh và bền vững phải dùng multipart upload, tăng prefix và/hoặc bật Transfer Acceleration.

How

Multipart: chia object thành nhiều phần song song, tối đa 10.000 part, mỗi part 5 MB–5 GB; lỗi chỉ cần retry part đó. Nên dùng khi > 100 MB, bắt buộc khi > 5 GB. S3 tự scale theo prefix: tối thiểu 3.500 PUT/COPY/POST/DELETE và 5.500 GET/HEAD mỗi giây, mỗi prefix — rải object qua nhiều prefix để tăng tổng throughput. Transfer Acceleration dùng edge location CloudFront + backbone AWS để giảm độ trễ. Tải xuống song song bằng byte-range fetch.

Clientfile lớn
→chia thành N part song song
UploadPart 1..N5 MB–5 GB mỗi part
→CompleteMultipartUpload
1 objectghép lại tự động
# aws s3 cp tự động dùng multipart cho file lớn; tăng độ song song

aws configure set default.s3.multipart_threshold 64MB
aws s3 cp ./big.iso s3://my-app-assets/data/big.iso --storage-class STANDARD

Tích hợp, replication & chọn dịch vụ

AWS8 Ứng dụng cần xử lý ngay khi có file mới: S3 Event Notifications hay polling?

What

Ứng dụng cần resize ảnh/scan virus mỗi khi có object mới. Giải pháp đúng là S3 Event Notifications (đẩy sự kiện) — không phải vòng lặp ListObjects liên tục (tốn request, trễ và không đảm bảo bắt kịp).

How

S3 phát event như s3:ObjectCreated:*, s3:ObjectRemoved:*, s3:ObjectRestore:* tới SNS, SQS hoặc Lambda — mỗi rule chỉ một đích, muốn nhiều đích thì tạo nhiều rule. Hoặc bật gửi mọi event sang EventBridge để lọc nâng cao và route tới nhiều target (kể cả SQS FIFO).

→event notification
EventBridge / SQS / SNSroute theo prefix
→batch / async
Lambda resizexử lý ảnh mới
# Route event ObjectCreated của prefix uploads/ tới một queue SQS
aws s3api put-bucket-notification-configuration \
  --bucket my-app-assets \
  --notification-configuration '{
    "QueueConfigurations": [{
      "QueueArn": "arn:aws:sqs:ap-southeast-1:111122223333:resize-jobs",
      "Events": ["s3:ObjectCreated:*"],
      "Filter": {"Key": {"FilterRules": [{"Name": "prefix", "Value": "uploads/"}]}}
    }]
  }'

Bẫy thi / Pitfall

Event notification tới SQS/SNS/Lambda cần cấp quyền cho S3 trong resource-based policy của đích (S3 ký với nguyên tắc s3.amazonaws.com). Event không đảm bảo thứ tự và có thể trùng (at-least-once) — code phải idempotent. Đừng quên: chỉ một đích mỗi rule.

AWS9 Ứng dụng đa vùng cần bản sao ở region khác: S3 Replication (CRR/SRR)

What

Ứng dụng chạy đa vùng cần bản sao object ở region khác (hoặc account khác) để giảm RPO và hỗ trợ DR/compliance. S3 Replication tự động copy object bất đồng bộ: CRR (cross-region) và SRR (same-region).

How

Bắt buộc versioning ở cả source và destination. Rule lọc theo prefix/tag, có thể replicate delete marker, giữ nguyên kiểu mã hoá (SSE-KMS cần quyền KMS), và chạy cross-account qua bucket policy + IAM role. Replication chỉ áp dụng cho object mới; dữ liệu đã có phải copy bằng S3 Batch Replication. S3 RTC đảm bảo SLA replicate trong 15 phút.

Multi-region
ap-southeast-1 (source)
my-app-assetsversioning ON
eu-west-1 (destination)
my-app-assets-drversioning ON
# Bật versioning hai đầu trước khi cấu hình replication
aws s3api put-bucket-versioning --bucket my-app-assets \
  --versioning-configuration Status=Enabled
aws s3api put-bucket-versioning --bucket my-app-assets-dr \
  --versioning-configuration Status=Enabled

# Copy dữ liệu ĐÃ CÓ sẵn sang bucket đích (replication không hồi tố)
aws s3 batch-ops create-job --account-id 111122223333 \
  --operation '{"S3ReplicateObject":{}}' \
  --report '{"Bucket":"arn:aws:s3:::ops-reports"}' \
  --manifest '{"Spec":{"Format":"S3BatchOperations_CSV_20180820"}}' \
  --priority 10 --role-arn arn:aws:iam::111122223333:role/batch-ops
KiểuPhạm viDùng khi
CRR (Cross-Region)Khác regionDR đa vùng, giảm latency cho user xa, compliance
SRR (Same-Region)Cùng regionGộp log, sao chép giữa hai account, test

Bẫy thi / Pitfall

Replication không hồi tố — object cũ không tự sang đích, phải dùng Batch Replication. Muốn tắt versioning ở source phải xoá cấu hình replication trước; nếu tắt ở đích, trạng thái object là FAILED. Cross-account cần cả bucket policy và IAM role; Object Lock source thì đích cũng phải bật Object Lock.

AWS10 So sánh S3 vs EBS vs EFS: chọn dịch vụ lưu trữ nào?

What

Ba dịch vụ lưu trữ hay bị nhầm trong đề: S3 là object storage truy cập qua HTTP API, EBS là block storage gắn vào một EC2 trong một AZ, EFS là file storage NFS mount được từ nhiều EC2/Lambda.

How

Chọn theo mô hình truy cập: cần mount như ổ đĩa cho một EC2 → EBS; cần file system dùng chung cho nhiều compute → EFS; cần lưu/đọc đối tượng qua API, web, CDN, backing cho static site → S3. S3 gần như vô hạn, durability 11 số 9; EBS giới hạn theo volume và gắn một AZ; EFS auto-scale, gắn nhiều AZ trong region.

Bẫy thi / Pitfall

S3 không mount được như ổ đĩa (trừ khi dùng Mountpoint for S3 / gateway). EBS không share giữa nhiều AZ — snapshot rồi tạo volume ở AZ khác, hoặc dùng EFS nếu cần mount chung. Đừng dùng EFS cho dữ liệu chỉ một EC2 dùng — EBS rẻ hơn; đừng dùng EBS cho nội dung phục vụ qua internet — S3 + CloudFront hợp hơn.
