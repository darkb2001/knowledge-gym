Q1 Reverse String không dùng hàm built-in

What

Đảo ngược chuỗi in-place bằng two pointers trên char[] — không dùng StringBuilder.reverse() built-in.

Why

Bài warmup phỏng vấn kiểm tra hiểu String immutable Java — mọi modify tạo object mới; char array swap O(1) space.

How

left=0, right=len-1, swap chars, move inward until left>=right. Handle null/len<=1 edge.

When

Palindrome prep, string manipulation interview. Pattern two pointers opposite direction.

When NOT

Không dùng built-in reverse() khi interview yêu cầu in-place. Không mutate String trực tiếp — immutable. Không recursive nếu stack depth concern n lớn.

Complexity Compare
ApproachTimeSpaceNote
Two pointers swapO(n)O(1)Optimal in-place
StringBuilder reverseO(n)O(n)Built-in disallowed interview
RecursiveO(n)O(n) stackNot preferred
 
public class ReverseString {
  public static String reverse(String s) {
    if (s == null || s.length() <= 1) return s;
    char[] chars = s.toCharArray();
    int left = 0, right = chars.length - 1;
    while (left < right) {
      char tmp = chars[left];
      chars[left++] = chars[right];
      chars[right--] = tmp;
    }
    return new String(chars);
  }

  public static void main(String[] args) {
    System.out.println(reverse("hello")); // olleh
  }
}
Use case

Reverse SKU barcode string warehouse scanner validation.

Pitfall / Interview trap

String immutable — s.toCharArray() first; Unicode surrogate pair rare edge.

Nói trong 60 giây
  • Two pointers left right swap char[].
  • O(n) time O(1) space in-place.
  • String immutable — toCharArray first.
  • Edge null length 0 or 1.
  • Pattern opposite direction pointers.

public class PalindromeCheck {
  public static boolean isPalindrome(String s) {
    int left = 0, right = s.length() - 1;
    while (left < right) {
      while (left < right && !Character.isLetterOrDigit(s.charAt(left))) left++;
      while (left < right && !Character.isLetterOrDigit(s.charAt(right))) right--;
      if (Character.toLowerCase(s.charAt(left++)) != Character.toLowerCase(s.charAt(right--)))
        return false;
    }
    return true;
  }

  public static void main(String[] args) {
    System.out.println(isPalindrome("A man, a plan, a canal: Panama")); // true
  }
}

  • LeetCode 125 classic.

import java.util.*;

public class FindDuplicates {
  public static List<Integer> findDuplicates(int[] nums) {
    Set<Integer> seen = new HashSet<>();
    List<Integer> duplicates = new ArrayList<>();
    for (int n : nums) {
      if (!seen.add(n)) duplicates.add(n);
    }
    return duplicates;
  }

  public static void main(String[] args) {
    System.out.println(findDuplicates(new int[]{1, 2, 3, 2, 4, 5, 3})); // [2, 3]
  }
}

public class FirstNonRepeating {
  public static Character firstNonRepeating(String s) {
    int[] count = new int[128];
    for (char c : s.toCharArray()) count[c]++;
    for (char c : s.toCharArray()) {

    return null;

Q5 LRU Cache — Doubly Linked List + HashMap

What

LRU Cache capacity K: HashMap key→node + Doubly Linked List order — get/put O(1) evict tail LRU.

Why

Design data structure interview LeetCode 146 — combine two structures for O(1) lookup + order.

How

Dummy head/tail. Get: move node to head. Put: exist update move head; new add head; if size>capacity remove tail prev map.

When

Cache eviction policy Redis-like local Caffeine internals concept.

When NOT

Không LRU khi cache size unbounded — memory leak. Không thread-unsafe HashMap+DLL concurrent — cần lock hoặc ConcurrentHashMap+linked (Caffeine). Không TreeMap O(log K) khi cần O(1) strict.

Complexity Compare
ApproachTimeSpaceNote
HashMap+DLLO(1) get/putO(K)Optimal design
TreeMap timestampO(log K)O(K)Simpler worse
 
import java.util.*;

public class LRUCache {
  private static class Node {
    int key, value;
    Node prev, next;
    Node(int k, int v) { key = k; value = v; }
  }

  private final int capacity;
  private final Map<Integer, Node> map = new HashMap<>();
  private final Node head = new Node(0, 0);
  private final Node tail = new Node(0, 0);

  public LRUCache(int capacity) {
    this.capacity = capacity;
    head.next = tail; tail.prev = head;
  }

  public int get(int key) {
    Node node = map.get(key);
    if (node == null) return -1;
    moveToHead(node);
    return node.value;
  }

  public void put(int key, int value) {
    Node node = map.get(key);
    if (node != null) {
      node.value = value;
      moveToHead(node);
      return;
    }
    node = new Node(key, value);
    map.put(key, node);
    addToHead(node);
    if (map.size() > capacity) {
      Node lru = removeTail();
      map.remove(lru.key);
    }
  }

  private void moveToHead(Node node) {
    removeNode(node); addToHead(node);
  }
  private void addToHead(Node node) {
    node.prev = head; node.next = head.next;
    head.next.prev = node; head.next = node;
  }
  private void removeNode(Node node) {
    node.prev.next = node.next; node.next.prev = node.prev;
  }
  private Node removeTail() {
    Node node = tail.prev;
    removeNode(node);
    return node;
  }
}
Use case

Local cache 1000 hot SKU product lookup WMS terminal.

Pitfall / Interview trap

Forget update map on evict; not thread-safe add lock.

Nói trong 60 giây
  • HashMap O(1) lookup node.
  • Doubly linked list access order.
  • Get/put move to head evict tail.
  • Dummy head tail simplify insert.
  • LeetCode 146 classic design.

import java.util.concurrent.*;

public class ProducerConsumerBlockingQueue {
  public static void main(String[] args) throws InterruptedException {
    BlockingQueue<Integer> queue = new ArrayBlockingQueue<>(5);
    ExecutorService pool = Executors.newFixedThreadPool(2);

    pool.submit(() -> {
      for (int i = 1; i <= 10; i++) {
        try {
          queue.put(i);
          System.out.println("Produced: " + i);
          Thread.sleep(100);
        } catch (InterruptedException e) { Thread.currentThread().interrupt(); }
      }
    });

    pool.submit(() -> {
      for (int i = 1; i <= 10; i++) {
        try {
          int item = queue.take();
          System.out.println("Consumed: " + item);
          Thread.sleep(200);
        } catch (InterruptedException e) { Thread.currentThread().interrupt(); }
      }
    });

    pool.shutdown();
    pool.awaitTermination(5, TimeUnit.SECONDS);
  }
}
import java.util.*;

public class ProducerConsumerWaitNotify {
  private final Queue<Integer> queue = new LinkedList<>();
  private final int capacity = 5;

  public synchronized void produce(int item) throws InterruptedException {
    while (queue.size() == capacity) wait();
    queue.offer(item);
    System.out.println("Produced: " + item);
    notifyAll();
  }

  public synchronized int consume() throws InterruptedException {
    while (queue.isEmpty()) wait();
    int item = queue.poll();
    System.out.println("Consumed: " + item);
    notifyAll();
    return item;
  }

  public static void main(String[] args) {
    ProducerConsumerWaitNotify pc = new ProducerConsumerWaitNotify();
    new Thread(() -> {
      for (int i = 1; i <= 10; i++) {
        try { pc.produce(i); Thread.sleep(100); }
        catch (Exception e) { e.printStackTrace(); }
      }
    }).start();
    new Thread(() -> {
      for (int i = 1; i <= 10; i++) {
        try { pc.consume(); Thread.sleep(200); }
        catch (Exception e) { e.printStackTrace(); }
      }
    }).start();
  }
}

Nói trong 60 giây

  • wait/notify synchronized while loop.
  • Production prefer j.u.c BlockingQueue.
  • Bounded buffer capacity backpressure.
  • ExecutorService thread pool same pattern.

public class LinkedListCycle {
  static class ListNode {
    int val;
    ListNode next;
    ListNode(int v) { val = v; }
  }

  public static boolean hasCycle(ListNode head) {
    ListNode slow = head, fast = head;
    while (fast != null && fast.next != null) {
      slow = slow.next;
      fast = fast.next.next;
      if (slow == fast) return true;
    }
    return false;
  }
}

import java.util.*;

public class TopKFrequent {
  public static int[] topKFrequent(int[] nums, int k) {
    Map<Integer, Integer> freq = new HashMap<>();
    for (int n : nums) freq.merge(n, 1, Integer::sum);

    PriorityQueue<Integer> minHeap = new PriorityQueue<>(
        (a, b) -> freq.get(a) - freq.get(b));

    for (int num : freq.keySet()) {
      minHeap.offer(num);
      if (minHeap.size() > k) minHeap.poll();
    }

    return minHeap.stream().mapToInt(Integer::intValue).toArray();
  }

  public static void main(String[] args) {
    System.out.println(Arrays.toString(topKFrequent(new int[]{1,1,1,2,2,3}, 2)); // [1, 2]
  }
}

Pitfall / Interview trap

Nói trong 60 giây

  • Min-heap size K maintain top.
  • O(n log K) better large n small K.
  • Bucket sort O(n) alternative.
  • LeetCode 347 pattern.

Q9 Sliding Window — Longest Substring Without Repeating

What

Sliding window longest substring without repeating — HashMap last index char, move start pointer skip duplicate.

Why

Subarray/substring contiguous constraint → sliding window not static window. O(n) each char visited twice max.

How

end pointer expand, lastSeen char if >=start move start. Update max end-start+1. Put lastSeen char end.

When

Substring max/min with constraint repeating char, at most K distinct.

When NOT

Không brute force O(n²) substring khi sliding window O(n) apply. Không quên move start = lastSeen+1 not lastSeen. Không fixed window khi constraint repeating chars — cần variable window.

Complexity Compare
ApproachTimeSpaceNote
Sliding window+MapO(n)O(k)k charset size
Brute forceO(n²)O(k)Check all substrings
 
import java.util.*;

public class LongestSubstring {
  public static int lengthOfLongestSubstring(String s) {
    Map<Character, Integer> lastSeen = new HashMap<>();
    int max = 0, start = 0;
    for (int end = 0; end < s.length(); end++) {
      char c = s.charAt(end);
      if (lastSeen.containsKey(c) && lastSeen.get(c) >= start) {
        start = lastSeen.get(c) + 1;
      }
      lastSeen.put(c, end);
      max = Math.max(max, end - start + 1);
    }
    return max;
  }

  public static void main(String[] args) {
    System.out.println(lengthOfLongestSubstring("abcabcbb")); // 3
  }
}
Use case

Max unique SKU sequence scan barcode stream.

Pitfall / Interview trap

start = lastSeen+1 not lastSeen; empty string return 0.

Nói trong 60 giây
  • Expand end shrink start window.
  • HashMap last index each char.
  • O(n) each char enter leave once.
  • Pattern contiguous substring.
  • LeetCode 3 classic.

import java.util.*;

public class SubarraySumK {
  public static int subarraySum(int[] nums, int k) {
    Map<Integer, Integer> prefixCount = new HashMap<>();
    prefixCount.put(0, 1);
    int sum = 0, count = 0;
    for (int num : nums) {
      sum += num;
      count += prefixCount.getOrDefault(sum - k, 0);
      prefixCount.merge(sum, 1, Integer::sum);
    }
    return count;
  }

  public static void main(String[] args) {
    System.out.println(subarraySum(new int[]{1,1,1}, 2)); // 2
  }
}

Q11 Graph BFS/DFS — Shortest Path (unweighted)

What

BFS shortest path unweighted graph vs DFS connected components — Queue level order vs stack recurse.

Why

BFS first reach = shortest hop unweighted. DFS simpler cycle/component. Warehouse AGV grid routing unweighted.

How

BFS: queue offer start dist 0, poll neighbors unvisited dist+1 until end. DFS: visited recurse neighbors count component.

When

BFS: shortest path maze grid word ladder. DFS: island count path exist all paths.

When NOT

Không BFS weighted graph — dùng Dijkstra. Không DFS shortest unweighted path — BFS first reach optimal. Không quên mark visited enqueue BFS.

Complexity Compare
ApproachTimeSpaceNote
BFSO(V+E)O(V)Shortest unweighted
DFSO(V+E)O(V)Components/path
DijkstraO(E log V)O(V)Weighted graph
 
import java.util.*;

public class GraphShortestPath {
  public static int shortestPath(List<List<Integer>> graph, int start, int end) {
    if (start == end) return 0;
    int n = graph.size();
    int[] dist = new int[n];
    Arrays.fill(dist, -1);
    Queue<Integer> queue = new LinkedList<>();
    queue.offer(start);
    dist[start] = 0;

    while (!queue.isEmpty()) {
      int node = queue.poll();
      for (int neighbor : graph.get(node)) {
        if (dist[neighbor] == -1) {
          dist[neighbor] = dist[node] + 1;
          if (neighbor == end) return dist[neighbor];
          queue.offer(neighbor);
        }
      }
    }
    return -1;
  }

  // DFS for connected components
  public static void dfs(List<List<Integer>> graph, int node, boolean[] visited) {
    visited[node] = true;
    for (int neighbor : graph.get(node)) {
      if (!visited[neighbor]) dfs(graph, neighbor, visited);
    }
  }

  public static void main(String[] args) {
    List<List<Integer>> graph = Arrays.asList(
        Arrays.asList(1, 2), Arrays.asList(0, 3),
        Arrays.asList(0, 3), Arrays.asList(1, 2, 4), Arrays.asList(3));
    System.out.println(shortestPath(graph, 0, 4)); // 3
  }
}
Use case

AGV grid shortest hop station to bin unweighted BFS.

Pitfall / Interview trap

BFS wrong weighted graph use Dijkstra; forget mark visited enqueue.

Nói trong 60 giây
  • BFS Queue shortest unweighted path.
  • DFS stack recurse components.
  • Both O(V+E) time.
  • dist array BFS level.
  • Weighted → Dijkstra not BFS.

Q12 Monotonic Stack — Next Greater Element

What

Monotonic stack next greater element — decreasing stack store indices, pop smaller when current larger assign result.

Why

Each element push pop once O(n) vs naive O(n²) compare forward.

How

For i 0..n: while stack not empty && nums[peek]<nums[i] result[pop]=nums[i]. push i. Remaining stack -1.

When

Next greater/smaller element, stock span, histogram largest rectangle.

When NOT

Không nested loop O(n²) next greater khi monotonic stack O(n). Không store value not index in stack. Không monotonic stack khi need all pairs compare — different pattern.

Complexity Compare
ApproachTimeSpaceNote
Monotonic stackO(n)O(n)Optimal
Nested loopO(n²)O(1)Naive
 
import java.util.*;

public class NextGreaterElement {
  public static int[] nextGreaterElements(int[] nums) {
    int n = nums.length;
    int[] result = new int[n];
    Arrays.fill(result, -1);
    Deque<Integer> stack = new ArrayDeque<>();

    for (int i = 0; i < n; i++) {
      while (!stack.isEmpty() && nums[stack.peek()] < nums[i]) {
        result[stack.pop()] = nums[i];
      }
      stack.push(i);
    }
    return result;
  }

  public static void main(String[] args) {
    System.out.println(Arrays.toString(nextGreaterElements(new int[]{2,1,2,4,3})); // [4, 2, 4, -1, -1]
  }
}
Use case

Next busier conveyor segment throughput compare.

Pitfall / Interview trap

Store index not value; circular array duplicate double loop.

Nói trong 60 giây
  • Stack decreasing indices.
  • Pop smaller when current bigger.
  • Assign result popped index.
  • O(n) each element once.
  • Pattern next greater element.

Q13 Binary Search — Classic & Binary Search on Answer

public class BinarySearchExamples {
  // Classic: find target in sorted array
  public static int binarySearch(int[] nums, int target) {
    int lo = 0, hi = nums.length - 1;
    while (lo <= hi) {
      int mid = lo + (hi - lo) / 2;
      if (nums[mid] == target) return mid;
      if (nums[mid] < target) lo = mid + 1;
      else hi = mid - 1;
    }
    return -1;
  }

  // Binary Search on Answer: min capacity to ship in D days
  public static int shipWithinDays(int[] weights, int days) {
    int lo = Arrays.stream(weights).max().getAsInt();
    int hi = Arrays.stream(weights).sum();
    while (lo < hi) {
      int mid = lo + (hi - lo) / 2;
      if (canShip(weights, days, mid)) hi = mid;
      else lo = mid + 1;
    }
    return lo;
  }

  private static boolean canShip(int[] weights, int days, int capacity) {
    int d = 1, load = 0;
    for (int w : weights) {
      if (load + w > capacity) { d++; load = 0; }
      load += w;
    }
    return d <= days;
  }
}

  • BS on answer monotonic feasible.
  • canShip helper check mid capacity.
  • lo max single hi sum weights.
  • Pattern minimize maximum.

import java.util.*;

public class TreeTraversal {
  static class TreeNode {
    int val;
    TreeNode left, right;
    TreeNode(int v) { val = v; }
  }

  // BFS Level-order
  public static List<List<Integer>> levelOrder(TreeNode root) {
    List<List<Integer>> result = new ArrayList<>();
    if (root == null) return result;
    Queue<TreeNode> queue = new LinkedList<>();
    queue.offer(root);
    while (!queue.isEmpty()) {
      int size = queue.size();
      List<Integer> level = new ArrayList<>();
      for (int i = 0; i < size; i++) {
        TreeNode node = queue.poll();
        level.add(node.val);
        if (node.left != null) queue.offer(node.left);
        if (node.right != null) queue.offer(node.right);
      }
      result.add(level);
    }
    return result;
  }

  // DFS Validate BST
  public static boolean isValidBST(TreeNode root) {
    return validate(root, Long.MIN_VALUE, Long.MAX_VALUE);
  }

  private static boolean validate(TreeNode node, long min, long max) {
    if (node == null) return true;
    if (node.val <= min || node.val >= max) return false;
    return validate(node.left, min, node.val) && validate(node.right, node.val, max);
  }
}

Pitfall / Interview trap

Nói trong 60 giây

  • DFS BST min max range check.
  • Both O(n) visit nodes.
  • Use long min max avoid int overflow.
  • Level order list of lists.

import java.util.*;

public class DynamicProgramming {
  // Climbing Stairs — O(n) space optimized
  public static int climbStairs(int n) {
    if (n <= 2) return n;
    int prev2 = 1, prev1 = 2;
    for (int i = 3; i <= n; i++) {
      int curr = prev1 + prev2;
      prev2 = prev1; prev1 = curr;
    }
    return prev1;
  }

  // Coin Change — min coins
  public static int coinChange(int[] coins, int amount) {
    int[] dp = new int[amount + 1];
    Arrays.fill(dp, amount + 1);
    dp[0] = 0;
    for (int i = 1; i <= amount; i++) {
      for (int coin : coins) {
        if (coin <= i) dp[i] = Math.min(dp[i], dp[i - coin] + 1);
      }
    }
    return dp[amount] > amount ? -1 : dp[amount];
  }

  // Longest Common Subsequence
  public static int longestCommonSubsequence(String text1, String text2) {
    int m = text1.length(), n = text2.length();
    int[][] dp = new int[m + 1][n + 1];
    for (int i = 1; i <= m; i++) {
      for (int j = 1; j <= n; j++) {
        if (text1.charAt(i - 1) == text2.charAt(j - 1))
          dp[i][j] = dp[i - 1][j - 1] + 1;
        else
          dp[i][j] = Math.max(dp[i - 1][j], dp[i][j - 1]);
      }
    }
    return dp[m][n];
  }

  public static void main(String[] args) {
    System.out.println(climbStairs(5)); // 8
    System.out.println(coinChange(new int[]{1,2,5}, 11)); // 3
    System.out.println(longestCommonSubsequence("abcde", "ace")); // 3
  }
}

Pitfall / Interview trap

Nói trong 60 giây

  • Coin change unbounded min coins.
  • LCS 2D if match diagonal+1.
  • Identify DP substructure overlap.
  • Bottom-up tabulation preferred.

import java.util.*;

public class Permutations {
  public static List<List<Integer>> permute(int[] nums) {
    List<List<Integer>> result = new ArrayList<>();
    backtrack(nums, new ArrayList<>(), new boolean[nums.length], result);
    return result;
  }

  private static void backtrack(int[] nums, List<Integer> path,
      boolean[] used, List<List<Integer>> result) {
    if (path.size() == nums.length) {
      result.add(new ArrayList<>(path));
      return;
    }
    for (int i = 0; i < nums.length; i++) {
      if (used[i]) continue;
      used[i] = true;
      path.add(nums[i]);
      backtrack(nums, path, used, result);
      path.remove(path.size() - 1);
      used[i] = false;
    }
  }

  public static void main(String[] args) {
    System.out.println(permute(new int[]{1,2,3}));
  }
}

Q17 Union-Find (Disjoint Set Union)

What

Union-Find DSU parent[] path compression + union by rank — O(α(n))≈O(1) find/union. Detect cycle undirected graph.

Why

Dynamic connectivity better than BFS each query. Kruskal MST cycle detection warehouse zone connect.

How

find(x) path compress parent. union(a,b) same root false cycle. rank merge attach smaller.

When

Connected components dynamic, Kruskal, detect undirected cycle, redundant connection.

When NOT

Không Union-Find directed cycle — DFS. Không BFS each query dynamic connectivity — UF near O(1). Không quên path compression union by rank.

Complexity Compare
ApproachTimeSpaceNote
Union-FindO(α(n))≈O(1)O(n)Amortized near constant
BFS each queryO(V+E)O(V)Static graph OK
 
public class UnionFind {
  private final int[] parent;
  private final int[] rank;

  public UnionFind(int n) {
    parent = new int[n];
    rank = new int[n];
    for (int i = 0; i < n; i++) parent[i] = i;
  }

  public int find(int x) {
    if (parent[x] != x) parent[x] = find(parent[x]);
    return parent[x];
  }

  public boolean union(int a, int b) {
    int rootA = find(a), rootB = find(b);
    if (rootA == rootB) return false; // cycle detected
    if (rank[rootA] < rank[rootB]) parent[rootA] = rootB;
    else if (rank[rootA] > rank[rootB]) parent[rootB] = rootA;
    else { parent[rootB] = rootA; rank[rootA]++; }
    return true;
  }

  public static boolean hasCycle(int n, int[][] edges) {
    UnionFind uf = new UnionFind(n);
    for (int[] edge : edges) {
      if (!uf.union(edge[0], edge[1])) return true;
    }
    return false;
  }

  public static void main(String[] args) {
    System.out.println(hasCycle(3, new int[][]{{0,1},{1,2},{2,0}})); // true
  }
}
Use case

Detect AGV zone graph redundant edge cycle before enable path.

Pitfall / Interview trap

Directed graph cycle need DFS not UF; forget path compression slow.

Nói trong 60 giây
  • Parent array find compress path.
  • Union by rank attach root.
  • Same root union → cycle undirected.
  • O(alpha n) amortized inverse Ackermann.
  • Pattern dynamic connectivity.

D1 Amortized O(1) — vì sao ArrayList.add() và HashMap.put() "nhanh"?

What

Amortized O(1) là chi phí trung bình trên cả chuỗi thao tác, không phải worst-case của một thao tác đơn lẻ. ArrayList.add() amortized O(1) nhưng lần resize là O(n); HashMap.put() amortized O(1) nhưng lần rehash là O(n).

Why

Câu hỏi phỏng vấn hay gài: "add() có phải O(1) không?" Trả lời đúng là O(1) amortized, worst-case O(n). Hiểu amortization giúp chọn đúng cấu trúc và lý giải trade-off giữa độ trễ và bộ nhớ.

How

ArrayList khi đầy tăng capacity khoảng 1.5 lần (old + (old >> 1)). Tổng chi phí copy cho n lần add từ đầu là n + n/1.5 + n/1.5² + … = O(n) → chia đều còn O(1). HashMap mặc định 16 bucket, load factor 0.75 → resize ×2 khi vượt threshold; từ Java 8, bucket có ≥ 8 phần tử chuyển thành cây đỏ-đen nên worst-case O(log n) thay vì O(n).

add phần tử thứ 10 → size = 10 (đầy)
↓ resize ×1.5: copy 10 phần tử sang mảng mới
capacity 10 → 15
↓ 5 lần add nữa đều O(1)
resize tiếp 15 → 22 — bình quân vẫn O(1)
When

ArrayList khi cần truy cập theo index nhanh và thêm cuối; HashMap khi cần tra cứu theo key; LinkedList khi chèn/xoá giữa/đầu nhiều và đã có con trỏ node.

When NOT

Không dùng ArrayList khi chèn/xoá giữa rất nhiều (O(n) dịch phần tử). Không nhầm "amortized O(1)" = "mọi thao tác O(1)". Với hệ thống nhạy latency, một lần resize O(n) vẫn gây spike → cấp phát trước bằng new ArrayList<>(n).

D2 Trie (prefix tree) — autocomplete & prefix search

What

Trie (prefix tree) là cây mà mỗi cạnh biểu diễn một ký tự; đường đi từ gốc tới một node tạo nên một tiền tố. Node kết thúc một từ được đánh dấu isEnd.

Why

HashMap tìm exact rất tốt nhưng không hỗ trợ truy vấn theo prefix (autocomplete). Trie tìm/kiểm tra tiền tố trong O(L) (L = độ dài chuỗi), độc lập với số lượng từ đã lưu, và duyệt được mọi từ theo prefix bằng DFS.

How

insert: duyệt từng ký tự, tạo node con nếu chưa có, đánh dấu isEnd ở node cuối. search: duyệt hết chuỗi và node cuối phải có isEnd. startsWith: chỉ cần duyệt tới hết prefix, không cần isEnd.

↓ cạnh "a"

↓ "t" → isEnd ("cat"); nhánh "r"→"t" ("cart")
t (end)  |  r → t (end)
When

Autocomplete / gợi ý từ khóa, spell-check, tìm kiếm theo prefix, IP routing (longest-prefix match), word search trên bảng chữ.

When NOT

Không dùng Trie khi chỉ cần tra cứu exact match — HashMap gọn và nhanh hơn. Không dùng mảng Node[26] cho Unicode/alphabet lớn (tốn bộ nhớ) — dùng Map<Character, Node>. Không dùng Trie cho dữ liệu ít khi truy vấn theo prefix.

import java.util.*;

public class Trie {
  private static class Node {
    Node[] child = new Node[26];   // a..z; dung Map cho Unicode/alphabet lon
    boolean isEnd;
  }
  private final Node root = new Node();

  public void insert(String word) {
    Node cur = root;
    for (char c : word.toCharArray()) {
      int i = c - 'a';
      if (cur.child[i] == null) cur.child[i] = new Node();
      cur = cur.child[i];
    }
    cur.isEnd = true;
  }

  public boolean search(String word) {        // tu day du
    Node n = walk(word);
    return n != null && n.isEnd;
  }

  public boolean startsWith(String prefix) {  // chi can tien to
    return walk(prefix) != null;
  }

  private Node walk(String s) {
    Node cur = root;
    for (char c : s.toCharArray()) {
      cur = cur.child[c - 'a'];
      if (cur == null) return null;
    }
    return cur;
  }
}
Use case

Pitfall / Interview trap

Quên isEnd thì search("car") sai khi chỉ mới có "cart". Mảng Node[26] tốn bộ nhớ khi ít từ — cân nhắc HashMap hoặc nén (radix tree / compressed trie).

D3 Graph nâng cao — Topological sort (Kahn) & Dijkstra

What

Topological sort sắp thứ tự tuyến tính các đỉnh của một DAG sao cho mọi cạnh u → v thì u đứng trước v (dùng Kahn BFS theo indegree, hoặc DFS). Dijkstra tìm đường đi ngắn nhất trên đồ thị có trọng số không âm bằng hàng đợi ưu tiên.

Why

Topo sort giải bài phụ thuộc: thứ tự build, lịch chạy task, môn học tiên quyết. Dijkstra cần vì BFS chỉ đúng khi cạnh không trọng số (mỗi bước = 1); có trọng số thì phải ưu tiên đỉnh gần nhất. Cả hai đều O((V+E) log V) khi dùng heap.

How

Kahn: tính indegree mọi đỉnh, đưa các đỉnh indegree 0 vào queue; pop ra, thêm vào thứ tự, giảm indegree láng giềng, ai về 0 thì enqueue. Nếu xử lý được ít hơn V đỉnh thì đồ thị có chu trình (không phải DAG). Dijkstra: dist[src]=0, dùng PriorityQueue lấy đỉnh có dist nhỏ nhất, relax các cạnh ra.

Tính indegree mọi đỉnh của DAG
↓ enqueue các đỉnh có indegree = 0
Pop đỉnh → thêm vào thứ tự → giảm indegree láng giềng
↓ láng giềng nào về 0 thì enqueue tiếp
Duyệt hết V đỉnh → hợp lệ; thiếu đỉnh → có chu trình
When

Topo: thứ tự build module, scheduler theo dependency, phát hiện chu trình trong DAG. Dijkstra: đường đi ngắn nhất có trọng số (định tuyến, logistics, khoảng cách mạng).

When NOT

Không dùng topo sort cho đồ thị vô hướng hoặc có chu trình — phải là DAG. Không dùng Dijkstra khi có cạnh trọng số âm (dùng Bellman-Ford), và không dùng BFS cho đồ thị có trọng số. Không quên bỏ entry cũ trong PriorityQueue (if (d > dist[u]) continue;).

import java.util.*;

public class GraphAdvanced {
  // Topological sort - Kahn (BFS): CHI dung cho DAG
  public static int[] topoSort(List<List<Integer>> g) {
    int n = g.size();
    int[] indeg = new int[n];
    for (List<Integer> nei : g) for (int v : nei) indeg[v]++;
    Deque<Integer> q = new ArrayDeque<>();
    for (int i = 0; i < n; i++) if (indeg[i] == 0) q.offer(i);
    int[] order = new int[n]; int idx = 0;
    while (!q.isEmpty()) {
      int u = q.poll();
      order[idx++] = u;
      for (int v : g.get(u)) if (--indeg[v] == 0) q.offer(v);
    }
    if (idx != n) return new int[0];   // co chu trinh -> khong phai DAG
    return order;
  }

  // Dijkstra - canh khong am, dung PriorityQueue {node, dist}
  public static int[] dijkstra(List<List<int[]>> g, int src) {
    int n = g.size();
    int[] dist = new int[n];
    Arrays.fill(dist, Integer.MAX_VALUE);
    dist[src] = 0;
    PriorityQueue<int[]> pq = new PriorityQueue<>((a, b) -> a[1] - b[1]);
    pq.offer(new int[]{src, 0});
    while (!pq.isEmpty()) {
      int[] cur = pq.poll();
      if (cur[1] > dist[cur[0]]) continue;          // entry cu, bo qua
      for (int[] e : g.get(cur[0])) {               // e = {neighbor, weight}
        if (dist[cur[0]] + e[1] < dist[e[0]]) {
          dist[e[0]] = dist[cur[0]] + e[1];
          pq.offer(new int[]{e[0], dist[e[0]]});
        }
      }
    }
    return dist;
  }
}
Use case

Sắp thứ tự build/khởi động các service theo dependency (topo), rồi tính chi phí/đường đi rẻ nhất giữa các node có trọng số (Dijkstra).

Pitfall / Interview trap

Topo chỉ đúng cho DAG — có chu trình thì order thiếu đỉnh. Dijkstra sai khi cạnh âm; và nhớ bỏ stale entry, nếu không vẫn đúng nhưng chậm hơn.
